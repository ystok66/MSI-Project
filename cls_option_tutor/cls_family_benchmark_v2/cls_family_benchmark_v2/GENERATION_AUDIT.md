# Generation Audit: CLS Family Benchmark v2

This pool is now generated by a stricter semantics-aligned process.

It does not hand-author `OUT:` lines. Instead it:

```text
1. selects source tasks from the real BASIC CLS dataset
2. screens for source tasks with better mixed/protect runtime family potential
3. clones them by consistently renaming lowercase vocabulary only
4. preserves exact renderer semantics by construction
```

## Regeneration method

Each candidate task is a semantic-equivalent clone of a screened source task:

- lowercase vocabulary is renamed bijectively
- colors are preserved
- grammar structure is preserved
- support/query outputs remain exact under the current renderer

The generator script is:

- [generate_semantics_aligned_candidates.py](/F:/SCAI/Learning-agent/cls_option_tutor/cls_family_benchmark_v2/cls_family_benchmark_v2/generate_semantics_aligned_candidates.py)

## Required acceptance pipeline

This candidate pool is not accepted by generation alone.

It must pass:

```text
1. structure sanity
2. exact render validation
3. runtime family validation
4. formal slice assembly
```

The exact generation contract is documented in:

- [docs/cls_option_tutor/FAMILY_BENCHMARK_TASK_ADAPTER_GENERATION_SPEC_20260421.md](/F:/SCAI/Learning-agent/docs/cls_option_tutor/FAMILY_BENCHMARK_TASK_ADAPTER_GENERATION_SPEC_20260421.md)

## Acceptance criteria after runtime validation

For mixed candidates:

- target family `MIXED_PROD_HARM` must be dominant
- `MixedProdHarmRate` must clear the formal threshold
- exact render must be valid

For protect candidates:

- target family `PROTECT_CRITICAL` must be dominant
- `ProtectCriticalRate` must clear the formal threshold
- exact render must be valid

If a task does not pass all gates, it remains candidate-only and does not enter
the formal slice.
